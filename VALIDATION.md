# Проверка реализации

Проверено локально 13 сентября 2026 года, Windows, Python 3.14.5.
Контейнер и CI настроены на Python 3.12.

## Выполнено

- `pytest -q -p no:cacheprovider`: **21 passed, 2 skipped** на SQLite (PostgreSQL-тесты запускаются в CI).
- Ruff: проверка исходников и форматирования.
- `pip check`: несовместимых зависимостей не найдено.
- `alembic upgrade head --sql`: успешно сформирован SQL начальной миграции PostgreSQL.
- FastAPI импортируется, OpenAPI генерируется, Uvicorn проходит startup.
- Панель открыта в браузере: проверены стартовая верстка, disabled-кнопки и ошибка неверного ключа.

Тесты покрывают:

- авторизацию по ролям, валидацию, CRUD товаров/FAQ/документов;
- обновление embeddings каталога, каскадное удаление и rollback при сбое провайдера;
- идемпотентность входящих событий, историю, неизвестный вопрос и безопасный fallback;
- структурированный ответ OpenAI SDK с подменённым HTTP transport;
- проверку источников и отказ от ответа с неизвестным ID;
- embedding cache и валидацию нечисловых значений;
- создание/назначение/закрытие обращения, запрет захвата чужим оператором;
- отсутствие AI-вызовов в операторском диалоге;
- feedback с проверкой владельца и повторные отрицательные оценки;
- rate limit и передачу человеку при недоступности Redis;
- outbox retry, успешную доставку с mock Telegram и порядок сообщений;
- repositories и повторяемый seed без дубликатов.

## Не выполнено в этой среде

- Реальный PostgreSQL/pgvector test: пропущен без `TEST_DATABASE_URL`.
- Запуск Docker Compose и сборка образа: Docker не найден.
- Online-применение/откат миграции и проверка Alembic drift: требуют PostgreSQL.
- Внешние запросы OpenAI и реальные сообщения Telegram: пользовательские ключи не предоставлены.
- Полный операторский сценарий через браузер: сервисный цикл проверен API-тестами,
  браузерная проверка ограничена экраном входа.
- Конкурентные PostgreSQL advisory/row locks не проверяются SQLite-тестами; для них добавлен
  отдельный тест дубля события и одновременного назначения операторов в CI.

В `.github/workflows/tests.yml` настроены pgvector integration test, миграции и Docker build.
Наличие workflow не означает, что GitHub Actions уже был запущен.

## Проверка после настройки окружения

1. Запустить Compose, seed и reindex по README; проверить `/health/ready`.
2. Задать боту вопрос о доставке, затем заведомо неподдерживаемой услуге.
3. Проверить контекст: назвать модель, затем спросить «Сколько он стоит?».
4. Нажать передачу оператору; открыть панель, взять обращение, ответить и закрыть.
5. Убедиться, что ответ доставлен в Telegram и outbox имеет статус `sent`.
6. Изменить цену через Admin API и проверить новый ответ и debug/search.
7. Проверить вопросы на своих документах и подобрать similarity threshold.
